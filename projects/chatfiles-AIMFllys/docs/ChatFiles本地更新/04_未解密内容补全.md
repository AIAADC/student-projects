# 04 · 未解密内容补全

> [!CAUTION]
> **除 QQ 正文、微信 `.dat` 与失败状态不得伪造的边界说明外，本页操作命令均为历史参考，不得执行。** 禁止按旧 02/03 流程覆盖解密目录、写 `data/wechat.db`、用旧 owner ID 计算 delta 或手工覆盖归档清单；所有现行操作必须走 [`06_现行安全管线.md`](06_现行安全管线.md)。

> "增量"不只是"新消息"，还包括**之前没能解密 / 没归档的内容**。本文逐类说明怎么补，以及哪些是**必须如实记录、不得伪造**的硬边界。

---

## 1. 之前没登录的微信账号

上次部署时没登录的账号，当时内存里没有它的密钥、解不了。这次：

1. 把该账号**登录上**（微信支持多账号切换；密钥进内存的前提是登录态）。
2. 按 [`02_重新解密解析.md`](02_重新解密解析.md) §1 把它解密到自己的 `work/decrypted/wechat/<新wxid>/`。
3. 重跑 `scripts/parseWeChat.ts`——它遍历**所有**账号，新账号的会话会以 `wx:<新account>:<username>` 形式进 `data/wechat.db`。
4. 这些会话在 [`03_增量提炼.md`](03_增量提炼.md) 里天然被判为 **new**（不在 `_state.json`），自动被全量提炼，无需特殊处理。

- [ ] 新账号的会话出现在 `data/wechat.db` 且被 delta 判为 new

## 2. `.dat` 加密聊天影像（延后增强）

微信聊天里的图片常以加密 `.dat` 落盘，[`scripts/archiveFiles.ts`](../../scripts/archiveFiles.ts) 默认**跳过**它们（`deniedAttachmentFile` 排除 `.dat`），所以它们没被归档。要补：

- 需要 **chatlog 的 img-key 解密**能力把 `.dat` 还原成 jpg/png（属本项目记录的"延后增强"，见 [`../../replication/docs/spec/05_archiving.md`](../../replication/docs/spec/05_archiving.md) 与 spec/10 边界）。
- 还原后的图片**只复制**进 `archive/`，再重跑归档即可（sha256 去重，不会重复）。
- **在该能力就绪前，MUST NOT** 把 `.dat` 当作普通文件硬塞，也不得用占位图伪装成真实影像。

- [ ] 若做了 `.dat` 解密：只记录还原图已安全进入版本化归档候选，不宣称 UI 已可见；若没做：在边界说明里如实标注"`.dat` 影像仍未解密"

## 3. QQ 正文：硬边界，如实记录

QQ 的 `nt_msg.db` 是自定义 `QQ_NT DB` SQLCipher（salt 不在 0 偏移），本项目**未解**。增量更新时**仍然**：

- **MUST NOT** 把 QQ 平台日志 / 缓存 / FTS 索引伪造成聊天正文。
- QQ 的**附件**（`nt_qq\nt_data` 下 Pic/Video/Ptt/File 明文）**可以**继续增量归档（重跑 `archiveFiles.ts` 即可）。
- 在边界文档里如实保留"QQ 正文未解密"的结论。详见 [`../../replication/docs/spec/10_data-products-and-boundaries.md`](../../replication/docs/spec/10_data-products-and-boundaries.md)。

- [ ] QQ 附件已增量归档；QQ 正文边界结论未被绕过 / 伪造

## 4. 其他派生数据的增量刷新（可选）

项目还有一批确定性派生脚本（`package.json` 的 `ingest:*`），它们多为"读现状重算"，重跑即刷新，幂等安全：

```powershell
# 例：刷新知识/课程/总结等派生板（按需挑跑，或一把跑全量 ingest）
npm run ingest:summary
npm run ingest:knowledge
# 课程站点（需 .env.local 配了 COURSE_URL，否则脚本会自动跳过）
npm run ingest:courses
```

> 这些产出（`data/*.json` / `*.md`）都在 gitignored 的 `data/` 下，重算只覆盖、无副作用。不确定就只跑你关心的那几个。
