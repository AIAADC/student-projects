## 1. 重解密到 `work/decrypted/`（含新登录账号）

确认微信主进程 PID（每次启动会变）：

```powershell
Get-CimInstance Win32_Process -Filter "Name='Weixin.exe'" |
  Select-Object ProcessId, CommandLine | Format-Table -Wrap   # 取无 --type= 的那个
```

对**每个要更新或新补的账号**重解密（只读原库、写副本，覆盖上次的 `work/decrypted/<wxid>/` 即可）：

```powershell
{{项目目录}}\work\crackv4.exe {{微信主进程PID}} `
  "{{微信数据根}}\{{wxid}}" `
  "{{项目目录}}\work\decrypted\wechat\{{wxid}}"
```

- **要补之前没解密的账号**：先把它**登录上**（密钥才在内存里），再像上面这样解密到它自己的 `work/decrypted/wechat/<新wxid>/`。`parseWeChat.ts` 会自动把新账号纳入。
- 工具链 / 方法细节见 [`../本地部署教程/03_解密解析归档.md`](../本地部署教程/03_解密解析归档.md) §1 与 [`../../replication/docs/spec/03_decryption.md`](../../replication/docs/spec/03_decryption.md)。

- [ ] 每个目标账号每库 `pages ok=N bad=0`

## 2. 整库重建 `data/wechat.db`

```powershell
cd "{{项目目录}}"
npx tsx scripts/parseWeChat.ts
```

跑完后，`data/wechat.db` 即"最新全量"。和更新前比一下，确认确实长了：

```powershell
python -X utf8 -c "import sqlite3;c=sqlite3.connect(r'data/wechat.db');print('conv/msg =', c.execute('select count(*) from conversations').fetchone()[0], '/', c.execute('select count(*) from messages').fetchone()[0])"
```

- [ ] 会话 / 消息总数 ≥ 更新前（新增了就会更大；新账号会带来新会话）

---

## 3. 增量归档新文件（幂等，直接重跑）

```powershell
npx tsx scripts/archiveFiles.ts
```

[`scripts/archiveFiles.ts`](../../scripts/archiveFiles.ts) 用 `sha256` + 同名最大序号去重，**重跑只会把新出现的文件补进 `archive/`**，已归档的不会重复。原文件不动。

- [ ] `data/library.json` 的 `stats.archived` ≥ 更新前

## 4. 重生成 digest + manifest（覆盖，得到"新基线对照面"）

```powershell
npx tsx scripts/prepChatDigests.ts
```

这会用**最新**的 `data/wechat.db` 重写 `work/chat-digest/*` 和 `data/insights/_manifest.json`。现在你手上同时有：

- `data/insights/_manifest.json` —— **更新后**的每会话 textCount（最新）
- `data/insights/_state.json` —— **已分析到**的高水位（[`01`](01_前置与快照.md) 固化）

下一步就拿这两者算 delta。

> 注意：`prepChatDigests.ts` 覆盖的是 `_manifest.json` 与 `work/chat-digest/`，**不动** `_state.json` 和 `data/insights/conv/*.json`——你的旧提炼成果安然无恙。

- [ ] `data/wechat.db`、`_manifest.json`、`work/chat-digest/` 已是最新
- [ ] `_state.json` 和 `data/insights/conv/*.json` **未被改动**（旧成果保留）
