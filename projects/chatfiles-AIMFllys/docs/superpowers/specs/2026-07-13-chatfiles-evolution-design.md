# ChatFiles 全面进化升级设计规格

## 1. 背景与目标

本轮在不破坏现有证据链、只读原始数据和本地优先边界的前提下，将 ChatFiles 从“聊天素材橱窗”升级为正式、克制、可长期使用的个人信息工作台。交付范围包含：

1. 重塑 Apple 风格的视觉系统、午夜书斋品牌标志与站点图标；
2. 简化聊天资料库布局、侧栏折叠、标题统计与主题切换；
3. 将聊天文字改为 Telegram 式时间轴，支持日期和发言人定位，并严格限制加载量；
4. 为链接卡片提供安全、有限、可降级的元数据解析；
5. 将右上角 AI 升级为可多步调用本地工具的检索智能体，支持高精度混合检索、文档定向读取与两种长上下文策略；
6. 提供只读的本地 HTTP、CLI 与 MCP 接口，供其他本地智能体连接。

项目继续遵守以下不可变约束：中文与所有文本保持 UTF-8；任何 `.ts/.tsx/.css` 文件不超过 300 行；原始微信、QQ 数据只读；个人数据、密钥、索引和缓存不进入 Git；AI 密钥仅在浏览器或当前进程内存中存在；网络服务只绑定 `127.0.0.1`；每个阶段完成验证后独立提交。

## 2. 现状与基线

- 技术栈为 React 19、TypeScript 6、Vite 8、Express 5、Node SQLite、Lucide。
- `data/wechat.current/wechat.db` 和会话素材索引已提供稳定消息身份、发送人、素材证据、分页和只读预览能力。
- 会话侧栏使用固定高度虚拟窗口，素材网格使用二维虚拟化；聊天文字目前仍复用素材卡片网格。
- AI 目前把单个会话转写全文一次性注入模型，只能进行一次普通对话调用，没有检索工具、文档读取或压缩策略。
- 站点 favicon 仍是 Vite 图标；主题切换使用三个并排图标；多个头像和分类使用高饱和果冻色。
- 2026-07-13 基线：`npm test` 共 275 项，273 通过、2 项平台条件跳过；`npm run build` 和 `npm run lint` 均通过。

## 3. 方案比较与选择

### 方案 A：只做视觉覆盖和前端拼接

优点是改动快；缺点是聊天文字仍通过素材查询和网格渲染，AI 仍靠全文硬塞，链接解析与本地接入没有可复用服务边界。该方案无法满足性能与智能体能力要求，不采用。

### 方案 B：在现有证据索引上分层演进（采用）

保留当前消息、素材、预览与安全解析模块，新增时间轴查询服务、链接预览服务、混合检索索引、智能体工具层和本地适配层。前端按展示职责拆分，HTTP、AI、CLI、MCP 共用同一批只读领域函数。优点是每阶段可独立验证和回滚，已有身份与路径安全测试继续生效；代价是需要增加若干模块和契约测试。

### 方案 C：重写为新的统一数据库和前端框架

理论上一致性更强，但会重新承担消息身份、素材证据、文件路径和预览安全风险，并让现有 275 项回归价值大幅下降。该方案违反本轮“进化而非推倒重来”的风险控制，不采用。

## 4. 品牌与 Apple 风格设计系统

### 4.1 视觉方向

视觉方向定义为“夜读档案室”：正式中性底色、精确分隔、少量蓝色命令色和暖铜品牌色。拒绝高饱和渐变、大面积糖果色、发光果冻块和多层玻璃。界面仍支持浅色、深色和系统偏好，但组件只使用语义 token。

核心 token 分为：

- 画布：`canvas / sidebar / content / elevated`；
- 文字：`primary / secondary / tertiary / inverse`；
- 结构：`separator / separator-strong / selection / hover`；
- 品牌：低饱和午夜蓝与暖铜，只用于品牌和关键命令；
- 状态：成功、警告、危险各一组前景和淡背景；
- 形状：普通控件 8px，浮层 12px，头像 22% 圆角或圆形；
- 动态：120–220ms，使用系统感 ease；在 `prefers-reduced-motion` 下取消位移。

头像不再按群聊/私聊随机使用鲜艳底色。默认头像使用中性石墨底和细边框，群聊用低饱和蓝灰，机主或当前选中项使用品牌强调色。材质仅允许在全局轨道、弹窗和固定工具条各使用一层，减少透明度时切换为不透明表面。

### 4.2 标志与 favicon

新“午夜书斋”标志采用一枚原创的单色 SVG：下部是展开的书页，上部以负形形成一弯月，书脊与月光在中心对齐。它同时表达阅读、夜晚和可检索档案，缩小到 16px 仍可辨识。品牌底色使用接近墨蓝的实色，浅色/深色分别使用反白或暖白图形，不使用渐变。

标志封装为可复用 `BrandMark` 组件；`public/favicon.svg` 使用同一几何，不再引用 Vite 图标。`index.html` 同时声明 SVG favicon、主题色和中文应用名称。

### 4.3 页面模式单按钮

左下角改为一个至少 36×36px 的主题按钮。首次读取系统偏好；单击按“跟随系统 → 浅色 → 深色”循环并保存选择，图标展示当前模式，`aria-label` 描述点击后的模式。主轨不再同时摆放三个按钮。

## 5. 聊天资料库布局

### 5.1 可折叠资料库侧栏

桌面端会话资料库保持独立列，标题右侧新增折叠按钮。折叠后保留 48px 的窄条、品牌化资料库图标和展开按钮，素材工作区获得更多横向空间；状态保存到 `localStorage`。移动端继续使用列表/工作区两页切换，不套用窄条模式。

侧栏搜索、固定集合、置顶和虚拟列表保持现有职责。折叠逻辑拆为纯状态模型与展示组件，避免把更多状态继续堆入 `ChatLibrary.tsx`。

### 5.2 两层工作区头部

原“身份行 → 独立统计行 → Tab/搜索行”压缩为两层：

1. 顶层：头像、会话名、会话类型；名称右侧直接显示 `产出总数 · 文字总数`，右侧保留置顶、AI 和移动端返回；
2. 控制层：分类 Tab、每类计数和搜索框。计数只出现一次，Tab 的紧凑徽标是对应分类的唯一明细计数。

头部固定在工作区顶部，滚动内容从其下开始。选中、加载、错误状态不改变头部高度，减少跳动。

## 6. Telegram 式聊天时间轴

### 6.1 展示模型

`聊天文字` 不再进入素材网格和 `ArtifactCard`。新增独立 `ChatTimeline`，按升序显示消息，使用日期分组和连续发言折叠：

- 每个日期有居中、可粘附的日期标记；
- 消息左侧是低干扰头像，正文为普通阅读流，不放进橱窗卡片；
- 发言人、精确时间和消息类型始终可见；连续同一人短时间发言只减少重复头像，但不隐藏第一条姓名；
- 每条消息带稳定 `message_uid` DOM 锚点和复制/筛选操作；
- 当前检索或跳转目标用短暂的语义高亮表示。

### 6.2 右侧时间与用户名轨

时间轴右侧增加窄工具轨：

- 日期按钮按月/日采样，点击后以该时间为锚点请求一页并滚动到最近消息；
- 用户按钮打开从右侧滑出的轻量弹层，包含搜索框、参与者列表、消息数和最近发言时间；
- 选择用户后，服务端只返回该发送人的记录，头部显示筛选 chip，时间轨也切换为该用户的日期分布；
- 从某条消息的姓名按钮触发筛选时，保留该消息 UID 作为锚点，筛选结果完成后自动定位并聚焦；
- 清除筛选恢复全会话，并回到最近锚点附近。

弹层使用原生 dialog 语义、焦点圈定、Escape 关闭和点击外部关闭。搜索只匹配服务端提供的规范 `sender/sender_name`，不自行猜测身份。

### 6.3 查询与性能

新增专用时间轴 API，不复用素材 offset 分页：

`GET /api/wechat/conversation/:id/timeline?limit=&before=&after=&around=&sender=&q=`

- `limit` 默认 120、最大 240；游标由 `time + message_uid` 组成，保证同一秒内稳定；
- 首次返回最近一页，前向滚动加载更早消息，必要时可从锚点向两侧加载；
- 返回 `pageInfo`、参与者摘要和按月/日压缩后的时间桶；参与者和时间桶可按会话与发送人缓存；
- 查询全部参数化绑定，`q` 对 `%/_/\\` 做字面转义；
- 前端最多保留相邻 5 页，约 600–1200 条消息；移出窗口的页以估算占位保留滚动位置；
- 消息正文使用 `content-visibility:auto`，网络请求用 `AbortController`，快速切换筛选时旧响应不能覆盖新状态；
- 跳转日期或用户时直接请求锚点页，禁止为了定位而从头加载所有记录。

## 7. 链接元数据解析

### 7.1 能力

链接卡片在进入可视区后按需请求 `GET /api/wechat/artifact/:id/link-preview`。服务端只接受已存在且分类为 link 的素材 ID，不接受任意 URL，依次解析：Open Graph、Twitter Card、HTML title、meta description、站点名和 favicon。公开响应只包含规范 URL、域名、标题、描述、站点名、图标 URL、状态和更新时间。

长度限制为：标题 80 个 Unicode code point、描述 180、站点名 40；控制字符、重复空白和 HTML 实体在返回前规整。卡片展示标题、两行描述和域名；解析失败、非 HTML、超时或无元数据时退化为域名与 Link 图标，卡片仍可安全打开原链接。

### 7.2 安全与容灾

- 仅允许 `http/https`；拒绝凭据 URL、环回、私网、链路本地、文件协议和解析后落入保留地址的主机；
- 每次重定向重新校验目标，最多 3 次；不携带 cookie、referer 或浏览器凭据；
- 连接与总请求超时 5 秒，只读取前 256KiB，Content-Type 非 HTML 时立即降级；
- 同域并发和全局并发受限；成功缓存 24 小时、失败缓存 30 分钟，缓存写入被 Git 忽略的 `work/link-preview-cache/`；
- 对测试注入 fetch/DNS 依赖，验证 SSRF、重定向、超长中文、乱码和降级路径。

## 8. 多步检索智能体

### 8.1 总体架构

AI 不再预先看到整库内容，而是看到工具目录和当前页面少量上下文。服务端新增有界智能体循环，最多 8 个工具步骤、每步最多 6 个调用、单次工具结果有字符上限。模型先理解问题并调用工具，服务端执行只读领域函数，再把带证据 ID 的结果反馈给模型；最终回答必须引用 `[消息:message_uid]` 或 `[文件:asset_id]`。

工具集合：

1. `list_conversations`：按名称、类型、日期列出会话；
2. `search_messages`：关键词/向量混合检索，可限定会话、用户和日期；
3. `get_message_context`：按消息 UID 取前后有限条原文；
4. `search_artifacts`：搜索作品、文档、Skills 与链接的名称和摘要；
5. `read_document`：按素材 ID 定向读取 TXT、Markdown、JSON、代码、HTML 和简单 DOCX 内容，分段并限制字符；
6. `get_timeline_slice`：按会话、发送人、日期取得一段规范时间轴；
7. `get_link_preview`：读取已缓存或安全解析的链接简介。

工具实现与 HTTP、CLI、MCP 共用领域服务，不通过服务端自请求 HTTP。所有结果去除绝对路径和隐私配置；文档读取再次走素材证据和允许根校验。

### 8.2 高精度混合检索

引入独立、可重建的 `data/ai-index.current.db`，它不是原始数据的权威副本。索引包含版本、来源指纹、会话/消息范围、UTF-8 正文块、FTS5 索引、实体字段和可选向量表。

检索分四路：

- 精确 ID、姓名、文件名、URL 域名优先；
- SQLite FTS5 BM25 负责关键词、短语和中文 n-gram 兜底；
- 可选 embedding 负责语义召回，模型、Base URL、维度和批大小均可配置；
- 结果用加权 Reciprocal Rank Fusion 合并，再按会话/用户/日期过滤和相邻证据扩展。

向量库采用可选 `sqlite-vec` 扩展；启动时检测二进制可用性，不可用时明确报告 `keyword-only`，FTS 与精确匹配仍完整工作。索引按 500–800 token、重叠 80 token 的会话块建立，保存首末消息 UID，向量只存数值与模型指纹。更换 embedding 模型或维度时创建新的 staging 索引，完整校验后原子激活，不把不同模型向量混用。

Embedding 配置存浏览器 localStorage；密钥仅在用户发起索引构建或查询的请求期间透传。支持任意 OpenAI 兼容 `/embeddings` 模型，也支持本机兼容端点。没有 embedding 配置时，智能体会用查询扩展 + FTS + 精确匹配，绝不伪称执行了向量检索。

### 8.3 智能体协议与降级

新增 `POST /api/ai/agent`，以 SSE 返回 `step/tool/citation/delta/done/error` 事件。上游支持 tool calling 时执行标准 JSON Schema 工具循环；不支持时先用本地混合检索取得证据，再执行一次带引用约束的普通生成。请求具有 90 秒总超时、上游中止传播、工具参数 schema 校验和稳定错误码。

前端 AI Dock 展示正在执行的工具步骤、证据数量、检索模式和可点击引用。点击消息引用切换到聊天文字时间轴并定位 UID；点击文件引用打开现有只读预览。旧的 `/api/ai/chat` 保留作为连接测试和兼容路径。

## 9. 长上下文策略

AI 设置中新增“最近窗口”和“无损摘要”两种明确可选策略，并配置模型上下文窗口。预算统一按模型窗口计算，至少保留 30% 给系统提示、工具结果和模型输出。

### 9.1 最近窗口（硬切）

最多把模型上下文窗口的 70% 用于原始上下文。预算优先级为：当前问题与最近对话 > 当前页面锚点附近原文 > 检索命中的原始证据 > 最近消息。按消息边界裁剪，禁止截断 UTF-8 字符或半条消息；界面清楚显示实际纳入的时间范围和遗漏数量。

### 9.2 无损摘要

摘要不是替代原始记录，而是版本化导航层。压缩采用分层 map/reduce：每段输出事实、人物、时间、直接引语、决定、分歧、未决项和来源消息 UID；上层只能合并，不得删除来源引用。摘要保存来源范围与内容 hash，原文变化后标记过期并重建。

每次回答仍动态注入：结构化摘要、当前问题检索出的原始证据、最近 20% 原始对话和当前锚点附近原文。这样摘要负责长期连续性，原始证据负责精确回答。若摘要模型失败或引用闭合校验不通过，自动回退最近窗口，不发布不完整摘要。

本地历史继续按会话保存，但只保存用户/AI 对话和小型结构化摘要，不保存 API Key。清除上下文只删除 AI 历史与摘要，不触碰聊天数据库和检索索引。

## 10. 本地 HTTP、CLI 与 MCP

### 10.1 共享只读服务

建立 `server/services/` 领域层，时间轴、检索、文档读取和证据查询都由纯参数函数提供。以下适配器只负责参数校验和序列化：

- HTTP：`/api/local/v1/status|conversations|search|artifacts|documents/:id|messages/:uid/context`；
- CLI：`npm run chatfiles -- status|conversations|search|artifacts|read-document|message-context`；
- MCP stdio：`npm run mcp`，暴露同名只读 tools 和资源模板。

CLI 默认访问 `http://127.0.0.1:3456`，支持 `--json` 输出稳定 UTF-8 JSON。MCP 使用官方 TypeScript SDK 和 stdio transport，不额外开放端口，适合小龙虾或其他本地 Agent 作为子进程连接。

### 10.2 安全契约

- 所有接口只读，不能删除、移动、改写、归档或解密文件；
- HTTP 继续仅绑定回环；可选 `CHATFILES_LOCAL_TOKEN` 使用 Bearer 校验，配置只从进程环境读取；
- 返回稳定 ID、相对显示信息和内容片段，不返回绝对路径、数据库位置或本地密钥；
- 结果默认 20 条、最大 100 条；文档与上下文有字符上限；
- MCP/CLI 错误只返回稳定 code，不回显原始路径、查询 SQL 或环境变量；
- 文档说明提供 Codex/Claude Desktop/其他 MCP 客户端的本地配置示例，示例不含真实身份和密钥。

## 11. 模块边界

前端新增或拆分：

- `components/brand/BrandMark.tsx`：唯一品牌图形；
- `features/chat-library/ChatLibraryShell.tsx`：折叠布局；
- `features/chat-timeline/*`：时间轴、右轨、用户弹层、分页 hook 和纯模型；
- `features/link-preview/*`：链接简介加载与展示；
- `components/ai/*`：Dock 壳、工具进度、引用、上下文状态；
- `utils/aiConfig.ts` 只保留配置与存储，流协议和上下文预算分别拆文件。

服务端新增或拆分：

- `server/services/chatTimeline.ts`：游标查询、参与者与时间桶；
- `server/services/linkPreview.ts`：安全抓取、解析、缓存；
- `server/services/search/*`：索引构建、FTS、向量与融合；
- `server/services/documents/*`：证据校验与文本抽取；
- `server/services/agent/*`：工具 registry、循环、预算和 SSE；
- `server/routes/localApi.ts`、`server/cli.ts`、`server/mcp.ts`：共享服务适配器。

任何接近 260 行的文件在增加职责前先拆分。类型放在 `src/types/` 或服务端领域类型文件；CSS 按 shell、timeline、popover、link、AI 子域分片，由现有聚合文件导入。

## 12. 阶段与验收

### 阶段 1：品牌与设计系统

完成 token、BrandMark、favicon、正式头像/导航/Tab 视觉和单图标主题切换。验证浅/深色、减少动态/透明度、高对比度、桌面与移动截图；运行单测、lint、build 后提交。

### 阶段 2：资料库与头部交互

完成侧栏折叠持久化和两层工作区头部。验证键盘、焦点、移动端、计数唯一性、布局无跳动后提交。

### 阶段 3：聊天时间轴

先为游标、字面搜索、用户筛选、日期锚点和 UTF-8 写失败测试，再实现 API、状态模型、分页窗口、用户弹层和右轨。验证超长夹具只挂载有限消息、快速切换不会串响应、跳转准确后提交。

### 阶段 4：链接解析

先覆盖 URL 安全、重定向、长度、HTML 解析与降级测试，再实现服务与可视区加载。验证失败时无死卡、无私网请求、中文不乱码后提交。

### 阶段 5：混合检索与 AI 智能体

依次实现索引 schema、关键词检索、可选向量、RRF、文档读取、工具 registry、8 步循环、SSE、上下文策略和引用跳转。使用完全本地夹具和假上游验证工具调用、多步检索、模型不支持工具时降级、摘要闭合与密钥不落盘后提交。

### 阶段 6：本地接口

完成共享服务、只读 HTTP、CLI、MCP 与配置文档。用子进程协议测试 MCP initialize/list/call，CLI 测试 UTF-8 JSON，HTTP 测试回环/token/限额/无路径泄漏后提交。

### 阶段 7：全量回归

执行 `npm test`、`npm run lint`、`npm run build`、服务端 API 回归、Playwright 桌面/移动/浅深色/键盘流程、浏览器控制台检查、UTF-8 与隐私 Git 自检、源文件 300 行检查。修复所有本轮引入的失败并提交最终验证记录。

## 13. 完成定义

只有同时满足以下条件才视为完成：

- 视觉不再出现 Vite 图标、果冻渐变或三按钮主题控件，新标志在 16/32/64px 清楚；
- 资料库侧栏可折叠恢复，工作区头部为两层且计数不重复；
- 聊天文字是独立时间轴，姓名和时间明确，日期/用户筛选与 UID 跳转可用，页面不会一次加载全部记录；
- 链接卡有受限简介，任何失败都稳定降级为图标和域名；
- AI 能在夹具中完成至少两次工具调用后给出带可点击证据引用的回答，关键词兜底始终可用，向量模型可配置并可明确降级；
- TXT、Markdown、JSON、代码、HTML 和简单 DOCX 能按素材 ID 定向读取且不暴露路径；
- 最近 70% 硬切和结构化摘要两种策略均有预算、失效和回退测试；
- 本地 HTTP、CLI、MCP 都能只读查询相同内容，限制、鉴权和 UTF-8 输出一致；
- 全部验证命令通过，本轮提交不包含 `data/`、`work/`、`archive/`、个人身份、密钥或用户已有未跟踪文件。
