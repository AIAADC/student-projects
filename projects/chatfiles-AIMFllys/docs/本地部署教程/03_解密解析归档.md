# 03 · 解密 · 解析 · 归档

> 本文把"原料"变成站点能读的数据：解密微信库（只对副本）→ 解析成 `data/wechat.db` → 归档有价值文件到 `archive/`。
>
> 三个环节的**深技术规格**分别在 [`03_decryption.md`](../../replication/docs/spec/03_decryption.md) / [`04_parsing.md`](../../replication/docs/spec/04_parsing.md) / [`05_archiving.md`](../../replication/docs/spec/05_archiving.md)。本文是**部署编排**：复用仓库现成脚本，按序跑通。
>
> 安全红线：**只读原始、只写副本到 `work/decrypted/`，原始库 / 文件一字不动。**

---

## 1. 解密微信库 → `work/decrypted/`

本机通常无 Go / 无 C 编译器，需自带工具链（解压 zip，无需管理员）。解密的稳妥方法是 `crackv4`：暴扫运行中微信进程的私有内存，取出每个库的**派生 encKey**（校验便宜：`macKey=PBKDF2(encKey,macSalt,2)` + page-1 HMAC，前置熵 / AES 首块预筛），再按 `pageSize 4096 / reserve 80 / salt=前16字节` 解密副本。**完整步骤、补丁、`crackv4` 算法见 [`03_decryption.md`](../../replication/docs/spec/03_decryption.md) 与 [`RUNBOOK.md`](../../replication/docs/RUNBOOK.md) Phase 2。**

核心命令形态（详见上述规格）：

```powershell
# 自带 Go + mingw 工具链到 work\，编译出 work\crackv4.exe（见 spec/03）
# 然后：只读原库 / 写副本到 work\decrypted（优先对 D:\ 备份根操作，无文件锁）
{{项目目录}}\work\crackv4.exe {{微信主进程PID}} `
  "{{微信数据根}}\{{wxid}}" `
  "{{项目目录}}\work\decrypted\wechat\{{wxid}}"
```

**✅ 解密验收**
```powershell
# 每个库都应 pages ok=N bad=0
{{项目目录}}\work\crackv4.exe {{微信主进程PID}} "{{微信数据根}}\{{wxid}}" "{{项目目录}}\work\decrypted\wechat\{{wxid}}" |
  Select-String 'DONE|bad='
# Python 读解密后的联系人（中文可读 = 成功）
python -X utf8 -c "import sqlite3;p=r'{{项目目录}}\work\decrypted\wechat\{{wxid}}\db_storage\contact\contact.db';print(sqlite3.connect(p).execute('select count(*) from contact').fetchone())"
```
- [ ] 每库 `[DONE] … pages ok=N bad=0`（**bad 必须为 0**）
- [ ] Python 能读到真实联系人数，中文不乱码

> 多账号：把每个**已登录**账号各解密到 `work\decrypted\wechat\<wxid>\`。只有当前在内存里有密钥（即登录中）的库才能取到 key——没登录的账号留到 [`../ChatFiles本地更新/`](../ChatFiles本地更新/) 在它登录后补。

## 2. 解析 → `data/wechat.db`（跑现成脚本）

```powershell
cd "{{项目目录}}"
npx tsx scripts/parseWeChat.ts
```

[`scripts/parseWeChat.ts`](../../scripts/parseWeChat.ts) 会遍历 `work/decrypted/wechat/` 下**所有**账号，把 zstd 压缩的消息体解开、用 `name2id` 还原发送人、按类型映射，落成明文 SQLite `data/wechat.db`（三表 `conversations` / `messages` / `contacts`）+ 索引 `data/wechat/index.json` + 可读 transcript 到 `work/chat-text/`。

> 重要特性：该脚本**每次都重建** `data/wechat.db`（先删后建），所以重跑安全、幂等——这也是 [增量更新](../ChatFiles本地更新/) 的基础。

**✅ 解析验收**
```powershell
python -X utf8 -c "import sqlite3;c=sqlite3.connect(r'data/wechat.db');print(c.execute('select count(*) from conversations').fetchone()[0],'/',c.execute('select count(*) from messages').fetchone()[0])"
```
- [ ] `data/wechat.db` 生成，`conversations` / `messages` 是真实数量
- [ ] 抽一条 `messages.text`，中文正常（zstd 解压 + name2id 还原 OK）

## 3. 归档有价值文件 → `archive/`（跑现成脚本）

```powershell
cd "{{项目目录}}"
# 若微信存储被迁出 C:\，确保 .env.local 里 WECHAT_STORE 已填（02 §6）
npx tsx scripts/archiveFiles.ts
```

[`scripts/archiveFiles.ts`](../../scripts/archiveFiles.ts) 枚举各账号 `xwechat_files\<wxid>\msg`（收到的真实 pdf / docx / 媒体）+ QQ `nt_qq\nt_data` 明文附件，**复制**进 `archive/` 并按一级分类归类，写索引 `data/library.json`。去重策略：同名取最大序号 + `sha256` 内容去重；加密 `.dat` 影像与缓存噪声跳过。**只复制，绝不动原文件。** 分类关键词在 [`scripts/shared.ts`](../../scripts/shared.ts) 等文件里是按本项目调过的默认值——**你可以按自己的学校 / 专业 / 兴趣替换其中的关键词**（如 `强基`/`基医`/`华科`/`hust`）以贴合你的数据。

**✅ 归档验收**
```powershell
node -e "const s=require('./data/library.json').stats;console.log('archived=',s.archived)"
```
- [ ] `data/library.json` 的 `stats.archived > 0`
- [ ] 按一级分类抽查，确有真实文档命中
- [ ] 原始源文件**一字未改**（归档为拷贝）
