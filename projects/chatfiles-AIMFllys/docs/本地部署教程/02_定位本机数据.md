# 02 · 定位本机数据（AI 自主全盘搜索）

> 本文是部署的"找原料"环节：让 AI **在你这台电脑上自主搜索**，定位你自己的微信 / QQ 聊天数据库与附件文件的**真实**存储位置，并识别解密所需的进程信息。
>
> 这一步**全程只读**：盘点、枚举、读文件头判断加密态——**禁止**对原始目录做任何删除 / 移动 / 改写。
>
> 深背景（目录 schema、迁移陷阱全解）见 [`../../replication/docs/spec/02_data-sources.md`](../../replication/docs/spec/02_data-sources.md)。

---

## 1. 为什么这一步最容易踩坑

微信 4.0 把数据放在名为 **`xwechat_files`** 的根目录下，**默认**在 `C:\Users\<你>\xwechat_files\`。但微信「设置 → 通用设置 → 文件管理 → 存储位置」允许把它**迁到任意盘符**。**一旦迁移，默认 `C:\…\xwechat_files` 就变成空壳，真实数据全在新位置。**

> 本项目早期排查就栽在这：盯着 `C:` 看，一个微信库都没找到，误以为"数据不存在"——真实数据被迁到了 D 盘。**所以第一动作永远是全盘搜目录名，而不是假设它在 C 盘。**

---

## 2. 全盘定位微信数据根（MUST，戳穿迁移陷阱）

```powershell
# 方法 A — 全盘搜目录名 xwechat_files（最稳）
Get-ChildItem -Path C:\,D:\ -Recurse -Directory -Filter xwechat_files -ErrorAction SilentlyContinue -Depth 6 |
  Select-Object FullName

# 方法 B — 若 A 没命中，按特征文件回溯（含 db_storage\session\session.db 的目录）
Get-ChildItem -Path C:\,D:\ -Recurse -File -Filter session.db -ErrorAction SilentlyContinue |
  Where-Object FullName -match 'db_storage\\session\\session.db' | Select-Object FullName
```

命中后向上回溯到 `xwechat_files` 根，记为 `{{微信数据根}}`。其下每个 `wxid_*` 子目录是一个**已登录过的账号**：

```
{{微信数据根}}\
├─ wxid_xxxx_xxxx\                  ← 一个账号（可能有多个）
│  ├─ db_storage\
│  │  ├─ message\message_0.db       ← 聊天主库（主账号常达数百 MB）
│  │  ├─ contact\contact.db         ← 联系人 + name2id
│  │  ├─ session\session.db         ← 会话摘要
│  │  └─ media_0.db / favorite\ …
│  └─ msg\                          ← 收到的真实文档 / 媒体（归档源，见 03 §归档）
└─ all_users\login\<wxid>\key_info.db   （非明文主密钥，仅元数据）
```

> 多账号时，**主账号** = `message_0.db` 最大的那个（本项目主账号 673MB 量级）。把要处理的账号目录记为 `{{wxid}}`。

---

## 3. 确认加密态（MUST 是已加密，证明定位对了）

```powershell
$p = "{{微信数据根}}\{{wxid}}\db_storage\message\message_0.db"
$bytes = [System.IO.File]::ReadAllBytes($p)[0..15]
($bytes | ForEach-Object { $_.ToString('x2') }) -join ' '
$hdr = -join ($bytes[0..14] | ForEach-Object { [char]$_ })
"header text = '$hdr'"   # 期望【不是】 'SQLite format 3'，而是高熵随机字节（已 SQLCipher 加密）
```

- [ ] 头 16 字节是随机、**非** `SQLite format 3\0` → 已加密，定位正确。

---

## 4. 定位 QQ 数据（附件可归档；正文是已知边界）

```powershell
Get-ChildItem -Path "$env:USERPROFILE\Documents\Tencent Files" -Directory -ErrorAction SilentlyContinue |
  Select-Object Name, FullName
```

- 数字目录名即你的 **QQ 号**（回填 `.env.local` 的 `QQ_NUMBER`）。
- `…\<QQ号>\nt_qq\nt_data\`（Pic / Video / Ptt / File）= **明文附件**，可归档。
- `…\<QQ号>\nt_qq\nt_db\nt_msg.db` = QQ 正文库，**自定义 `QQ_NT DB` SQLCipher，本项目未解**——属已知边界，**禁止**伪造（见 [`../../replication/docs/spec/10_data-products-and-boundaries.md`](../../replication/docs/spec/10_data-products-and-boundaries.md)）。

---

## 5. 识别微信主进程 PID（解密下一步要用）

```powershell
Get-CimInstance Win32_Process -Filter "Name='Weixin.exe'" |
  Select-Object ProcessId, CommandLine | Format-Table -Wrap
```

渲染 / GPU / utility 子进程命令行都含 `--type=…`；**主进程没有 `--type=`**。把那个唯一的 `ProcessId` 记为 `{{微信主进程PID}}`。

---

## 6. 回填 `.env.local` 并产出定位结论

把找到的真实路径回填：

```ini
WECHAT_STORE={{微信数据根}}     # 仅当它不在默认 C:\Users\<你>\xwechat_files 时需要
QQ_NUMBER=<你的QQ号>
```

给机主一份简明结论（数据根在哪、是否被迁移、有几个账号、主账号是谁、主进程 PID、QQ 号），再进入下一步。

**✅ 本步验收**
- [ ] 找到 `{{微信数据根}}\{{wxid}}\db_storage\message\message_0.db`（数百 MB）且头字节为高熵（已加密）
- [ ] 记下唯一无 `--type=` 的 `Weixin.exe` 主进程 PID
- [ ] 找到 QQ `Tencent Files\<QQ号>\nt_qq`（如有 QQ）
- [ ] 原始目录**一字未改**（全程只读）
