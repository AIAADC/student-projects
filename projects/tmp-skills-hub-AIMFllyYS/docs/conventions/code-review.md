# Code Review 检查清单

> 本文档是 `AGENTS.md` 中 review 条款的完整版。
> AI 编码代理在进行 code review 或自我审查时按本清单逐项检查。

## 分层与依赖方向

- core 是否引入了框架依赖、网络或进程管理？（只允许 Node 标准库 + 文件 I/O）
- web 是否直接 import 了 core 或 cli？（必须走 HTTP `/api`）
- 是否有对 `@skills-hub/core/dist/...` 一类深路径的导入？（只允许包入口）

## 确定性内核（改到 core 时必查）

- store 是否被原地修改？（更新必须产生新哈希的新版本）
- symlink 集合变更是否原子？（临时目录建好一次替换，不允许逐个增删）
- 哈希逻辑的三条不变量是否被破坏？（排序、路径参与、原始字节——见 [core-patterns.md](./core-patterns.md)）
- 哈希忽略清单是否被改动？（改了 = 全库哈希迁移，必须有对应 issue）
- 确定性逻辑是否带了单元测试？

## 产品红线

- 是否存在未告知用户就移动/修改其本地 skill 目录的代码路径？（包括测试代码）
- 本地服务是否只绑 `127.0.0.1`？是否引入了未经用户显式发起的写操作？

## 职责边界

- 新增的功能是不是文本判断类？（审查/分类建议/"有用"判定应写成 Skill 交给 Agent，不写成代码）
- 文件/函数是否过长且未按职责拆分？（关注职责混杂与自然接缝，而非行数本身）
- 单处使用的代码是否被过早提升到共享位置？

## 通用

- 是否出现 `any`？（用 `unknown` + 类型收窄）
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 是否全部通过？
- Commit 是否符合 Conventional Commits，scope 是否用了包名？
