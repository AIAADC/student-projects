## 后置，但不要忘

| 项 | 为什么后置 | 被什么挡住 |
|---|---|---|
| 浏览器插件（十秒内收录） | 为了把「存一个 skill」压到十秒才会自然出现 | 先有 App 和链接收录 |
| 账号 / 统一登录 / 鉴权 | 不做就玩不出社区；可用授信仓库绕过 | 先有统一查看和分享（分享 = 批 11） |
| 登录与上一项目打通（幂等） | 不一定能直接接，但开始时要保证可幂等接入 | 先确认旧登录是否还在 |
| 使用量统计 | 服务评估，也服务个人主页 | 先有「用」的事实数据 |
| 个人主页（在用什么 / 精选置顶） | 按人看前端 skill，比逛市场更合理 | 统计 + 账号 |
| 全站精选 / 排行 | 社团内部就会觉得「愿意用」 | 使用数据 |
| 各客户端 YAML 精致适配（display name 等） | 不影响「放在目录里就能被发现」 | 通用 name / description 先通 |
| 链接变更后不重启 IDE 即看见（#166） | 要先查各家有没有官方热加载入口；禁止重写加载器 | 磁盘链接已能改；热加载机制未查清 |
| 官方/插件 skill 收录边界与跨客户端启用（#168） | 分类口径未定；搬官方副本会再生、链错客户端会空转 | 发现层只排除 root 形状，不分类 skill |
| 千级技能换存储介质 | 现在用目录即可 | 真到 1000+ 再换 |
| 「有用」的识别与治理（很多 PPT skill 只用两个） | 不是 Step 1；词在不同场景意思不同 | 先有库存和查看 |
| 比官方更好的按任务加载 / 上下文裁剪 | 各 Agent 已有方案；第一天不必替它们实现 | 先保证能用 |
| 公开包管理器、对标 skills.sh | 用户不是全网用户；做不过成熟产品 | 产品定位已否决为第一目标 |
| 市场调研 / 问卷补 Step 6 之后的需求 | 成熟公司才有专人；现在用自己人在用的前提提需求 | 先用起来 |
