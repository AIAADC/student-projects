## 2. 全景路线图（Step 1 → Step 6）

这是一次**方向性布局**：先问清产品，再顺着用户的决策一步一步走。会上明确说过「这不一定是一二三四五的」——甬道是讲解思路，不是严格的施工顺序。

### 开场三问

- **服务谁？** 普通用户，还是长时间运行的自动化 Agent？→ 服务的是人，而且限定为**社团自己**。不是开源市场上的所有人——那些人会去用 skills.sh / CC Switch，「你就跟他真不了」。
- **管什么资产？** → **Skill**。本质是一个文件夹，`SKILL.md` 里的 `name` + `description` 所有客户端都能读；各家 YAML 扩展（如 display name）是精致适配，不是能不能用的门槛。
- **CRUD 在哪？** 没有 CRUD 就没有业务。从用户的第一决策出发自上而下走，走到可以停的地方停下来，把接口先抽象出来。

### Step 1 存 —— 把有用的 skill 存下来

- 现状：skill 散在 `.claude`、`.agents` 和别的客户端目录里，要解决的是**互通**。
- 做法：把各处的东西拉到一个统一的地方（会上举例：假设自己是 spm，就放 `.spm/skills`）。
- 去重按**整个文件夹内容的哈希**，不按文件名；哈希唯一标识一个 skill，系统要维护「哈希 ↔ skill」的对照。
- 以后有 1000+ 个 skill 再考虑换存储介质；现在先把接口抽象出来，用文件目录存。
- 授权先讲清楚：产品要宣称「我要管你的 skill」，不能安装后静默把用户已有的东西搬走。

### Step 2 用

- Skill 本来就在各 Agent 的目录（链接位置）上，Agent 现在就能用。
- 「什么时候加载哪些 skill」每个 Agent 有自己的解决方案；更好的检索、按任务裁剪上下文是以后自己的 focus，第一天不做。

### Step 3 改

- Agent 本来就能改。改到的是符号链接指向的**原文件**，所以是全局改——skill 不会漂移，在 Claude 里改和在 Codex 里改，落到的是同一份。

### Step 4 删

- 删的是符号链接，原件还在；Agent 从此读不到，就等于卸下了。

### Step 5 项目与全局

- 项目级 / 全局隔离各编码 Agent 已经做了（用户目录下的 skills 全局可见，项目内的只有该项目可见），是「程序设计里被做过一万遍的标准做法」。
- 我们只决定：符号链接挂在全局侧还是项目侧。从 Step 3 到 Step 5，「有些东西你都不用做，有些东西就是一句话的事」。

### Step 6 统一看 —— 第一件可交付

- 从 1 做到 5 之后，用户下一步是「我要一个地方统一的看」→ 做一个 App（web app 或别的壳）。**到 Step 6 为止，就是可以做的第一件事**——先有一个能用起来的东西，再来讨论需求。
- 固定需求不辩论：搜索框、分类（至少识别来源）、打 tag。做或不做可以决定，但不花会议时间讨论定义。
- 提需求的前提是你在用 skill；接下来要讨论的是**最高杠杆**的需求，不是随口一句。

### Step 6 之后的方向布局（想到了就从第一天躺进列表，不是第一天做）

- **收录路径**：现在用户走 GitHub（skill installer / 手动 clone）或对 Agent 说「帮我存」，新入口要兼容这些路径。要把「存一个 skill」压到十秒内，自然会走到浏览器插件——第一天可以不做，但要写进文档，让所有人从第一天知道这里以后可能有个插件。
- **共享**：社团要的是 skill 库 + 共享。共享会引出账号系统 / 统一登录 / 上云；现在绕过——把所有成员当授信用户，往一个统一仓库写，别人用链接从统一的地方拿。不做局域网分享（人不全在局网），直接上云 / 用 Git。
- **社区玩法**：统计 skill 使用量（服务评估）→ 个人主页展示每个人在用什么（知道他做前端，就去看他的前端 skill）→ 主页精选置顶 → 全站精选、排行。做到这里，没有 AI 的东西社团的人也愿意用。这些被「账号 + 使用数据」挡住；不做账号，社区玩法永远玩不出来，所以愿意以后做。上一项目若已有登录，接入至少保证幂等，不假设能直接接过来。
- **明确不走**：面向所有人的公开包管理器 / 对标 skills.sh。现在的用户不是那种用户，做一个「看上去谁都能用」的东西做不过成熟产品；「真不了的时候回归本质」——要的是社团内部能用，人不多，社区干净。

### 把讨论收成工程的方法

- 把线性鱼骨收成一张**工程 DAG**：识别核心块（比如 App 壳），把每块要处理的事标出来，就可以 block。
- 后端没有统计 skill 使用时，前端交付不了主页 / 排行——依赖画在图上，就知道第一、第二、第三做什么。
- 用同样的方式和 AI 讨论，让它整理成工程规划、按进度推，能并行的并行；前提是每个 issue 写对。
