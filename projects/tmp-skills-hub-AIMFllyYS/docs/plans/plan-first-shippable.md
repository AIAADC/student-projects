# 第一版工程计划（决策甬道 1–6 落地）

> Created: 2026-08-16
> Updated: 2026-08-16
> Status: draft
> Source: [第一次同步会：原文与全景路线图](../updates/meeting-2026-08-15-first-sync.md) · [架构初始规范](../designs/architecture-initial-spec.md)
> 会上的要求：把线性鱼骨收成一张工程 DAG，识别核心块，依赖画在图上，issue 写对了才允许并行。本文就是那张图的第一版。

## 目标

把决策甬道 1–6 做成社团成员能用的第一版：技能被收进统一库存、各 Agent 照常能用能改、大家能在一个页面里统一看，并且能通过授信仓库分享。

## 核心块与依赖 DAG

```text
[M0 约定] ──→ [M1 库存与镜像]（块 A，地基）
                    │
                    ├──→ [M2 App 壳：统一看]（块 B，第一件可交付）
                    │
                    └──→ [M3 GitHub 链接收录]（块 A 扩展）
[M0 约定] ──→ [M4 授信仓库分享]（块 C，可与 M2 并行）

[块 D 社区与统计]（账号 + 使用数据双重 block，本计划不做，画在图上）
```

## 里程碑

### M0 约定（无依赖，先定案）

- 统一库存目录的名字与位置（会上举例 `.spm/skills`，最终名字待定）。
- 资产口径：一个 skill = 一个文件夹，入口 `SKILL.md`，`name` + `description` 是收录最低要求；`name`/路径一律英文。
- 身份口径：整个文件夹内容的哈希唯一标识一个 skill，系统维护「哈希 ↔ skill」对照。
- 四个接口先抽象、只做最简实现：存储介质、收录来源、客户端适配、身份接入（见架构规范第 5 章）。

### M1 库存与镜像（块 A，依赖 M0）

- 扫描本地各客户端目录（`.claude`、`.agents` 等），把已有技能镜像进统一库存。
- 内容哈希去重（不按文件名）。
- 在各 Agent 目录放符号链接指回原件：读 / 改 = 原件（全局改，不漂移）；删链接 = 卸下；项目级 / 全局 = 链接挂哪一侧。
- **收录前明确告知并获得授权**，绝不静默搬走用户已有技能。
- 前置 spike：Windows 上符号链接的权限与行为验证（单独 issue）。

### M2 App 壳：统一看（块 B，依赖 M1 的数据产出格式）

- Web 应用（本仓库 `apps/web`，Vite + React SPA，数据来自 CLI 本地服务 `/api`）：列表 + 搜索 + 按来源分类 + tag。
- 搜索、来源、标签是固定需求，跟列表同一迭代做，不单独立项争论。
- 骨架可以用样例数据先行，与 M1 并行开发，在真实库存格式上合流。

### M3 GitHub 链接收录（块 A 扩展，依赖 M1 的收录来源接口）

- 用户给一个 GitHub 链接，我们代为收录进统一库存。
- 兼容既有路径：对 Agent 说「帮我存」、手动 clone，不拦截、不接管。

### M4 授信仓库分享（块 C，依赖 M0，可与 M2 并行）

- 全员授信，往统一 Git 仓库写；别人用链接从统一的地方拿。
- 不做账号、不做局域网分享，直接走云上 Git 托管。

## 不做（本计划）

块 D 及其依赖全部后置，逐条见 [backlog-from-first-sync.md](../issues/backlog-from-first-sync.md)：账号 / 统一登录、使用量统计、个人主页、精选排行、浏览器插件、公开包管理器、「有用」的自动判定、千级技能换存储介质。

## Issue 纪律

- 每个 issue 写清：属于哪个块（A/B/C/D）、依赖哪些 issue、被谁 block。
- 能并行的并行（M1 与 M2 骨架、M2 与 M4），前提是依赖写对。
- 创建 issue / 由 issue 出 PR 按 AGENTS.md 的强制 skill 流程走。

## 验收

- 社团成员能在页面上看到已收录的 skill（`name` + `description` 至少可读）。
- 同一内容不会因文件名不同存两份。
- 在常用 Agent 目录里仍能发现、使用、修改这些 skill，且改动落在同一份原件上。
- 不要求用户先注册账号。
- 没有在未告知的情况下搬走用户本地技能。

## 风险

- 远程 [KinomotoMio/skill-hub](https://github.com/KinomotoMio/skill-hub) 仍是空仓，当前账号无写权限，代码先在本地长。
- 各客户端 YAML 扩展字段不一致；第一版只保证通用 `SKILL.md` 的 `name` / `description`。
- 符号链接在 Windows 上可能需要额外权限，M1 前置 spike 单独验证。
